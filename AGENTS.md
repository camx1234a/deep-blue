# DeepBlue Rescue agent guide

## Project shape

- This is a Java 21 Spring Boot 4.1.1 application built with the Maven Wrapper.
- Main code lives under `src/main/java/com/deepblue/rescue/` and is organized as:
  - `domain/`: JPA entities and domain enums.
  - `repository/`: Spring Data JPA repositories and derived/JPQL queries.
  - `service/` and `service/impl/`: application services and their implementations.
  - `dto/` and `mapper/`: request/response contracts and MapStruct mappings.
  - `exception/`: application-specific exceptions.
- Database migrations are Flyway scripts in `src/main/resources/db/migration/`. Hibernate uses `ddl-auto: validate`, so schema changes belong in a new migration rather than being generated by Hibernate.

## Build and test

- Use `./mvnw` on Unix-like shells or `./mvnw.cmd` in Windows PowerShell.
- Run the full verification suite with `./mvnw.cmd test` on Windows.
- Run one focused test with `./mvnw.cmd -Dtest=RescueCaseServiceImplTest test` or the relevant test class name.
- Persistence tests use Testcontainers and PostgreSQL. Docker must be available before running `PersistenceIntegrationTest` or the Spring context tests that import `TestcontainersConfiguration`.
- Prefer the Maven Wrapper over a globally installed Maven version.

## Implementation conventions

- Preserve the existing package structure and public APIs unless the requested change requires a contract change.
- Keep persistence concerns in repositories and entity mappings; keep orchestration and business rules in services.
- Use domain methods such as `RescueCenter.addCase`, `RescueCase.assignAnimal`, `Animal.assignMedicalRecord`, and `Specialist.addExpertise` when changing relationships so both sides remain synchronized.
- Match existing Spring Data method naming and query style before introducing custom queries.
- Use MapStruct mappers for entity/DTO conversion where a mapper already exists; do not duplicate mapping logic in services.
- Add or update a focused unit test for service behavior and a persistence integration test when changing mappings, migrations, constraints, or repository queries.
- Use Flyway versioned filenames such as `V4__short_description.sql` for schema updates and keep migrations forward-only.

## Configuration

- Local PostgreSQL defaults are `jdbc:postgresql://localhost:5432/deepblue`, user `postgres`, password `postgres`.
- Override database settings with `DB_URL`, `DB_USER`, and `DB_PASSWORD`; do not commit credentials or machine-specific configuration.
- Keep SQL logging and migration behavior consistent with `src/main/resources/application.yaml` unless the task explicitly changes runtime configuration.
